# Step 803-1 — app accounts made by the core, the last architect kept, the choice of the single sign-in door

**Task** (core step 803-1, the owner's go 2026-11-19, through the core's main agent). Measured on the owner's factory server: the
birth window's element admin was created in app `node` (`grantElementAdmin` / `insertAccount` hard-coded it); on the element's own
site `admittedTo(siteApp, node account)` admits only the architect and a guest, so the admin was refused, the form offered
registration, and a second account of the same e-mail was born in the element's app with role `user`.

**What changed**
1. `lib/auth/node-users.ts`: `POST /api/node-users/element-admin` and `POST /api/node-users` take an optional `element`
   (`appForElement`): an element with an app organization (554-1) → the account is looked up and created in that app (an existing
   one gets the role, its password never touched); absent, or no app organization → `node` as before; malformed → 400 `bad-element`.
2. `runBatch`: the last active architect of app `node` is never anonymized, set inactive (`block`, `update {blocked:true}`) or
   stripped of `architect` (`removeRole`, `update {roles}`) — skip reason `last-architect`, counted inside the transaction.
3. `app/api/auth/sso/route.ts`: a session the site admits but whose account belongs to another app (not a guest) → 302 to the new
   page `/continue-as` (`app/(auth)/continue-as/`): «Continue as {email}» (`confirmed=1` — the code, as before) or «Sign in with
   another account» (`/logout` → `/login` with the same return). Words ru / en verbatim from the task, other languages → English
   (`Accept-Language`, first tag). `proxy.ts` opens the page (AUTH_PAGES), `scripts/check-routes.mjs` lists it.
- README of `/api/node-users` documents 1 and 2.

**Checks** — `npm run test:element-admins` (production build, real HTTP, fresh database, a test factory node with the app `shop`
on its own domain and `plain` without an app organization): 24 checks passed, 10 of them new (803-1 (1) ×4, (3) ×4, (2) ×2), with
negative controls: no element / an element without an app → the node account; the app's own person and a site without an app →
the code at once; two architects → one may go. Spoil-and-restore: all three rules spoiled in one build → 7 of the new checks
failed (1: three, 3: two, 2: two), restored → green. `npm run prebuild` RC=0.

**Not checked** — the live factory server (no push, no tag: the push waits for the owner); the core's birth window sending
`element` (the core's side).

**Mistakes** — two spoil runs failed at the type check (`false && user.id`, a comparison with an impossible action) before the
runtime spoil via an environment flag worked.
